### 10 приоритетов на ближайший квартал

1. 🔴 **Баг: категории «Сухий лід» и «Харчовий лід» показывают идентичный список товаров** (`src/lib/products.js:191`). Две коммерческие посадочные с одинаковой выдачей = каннибализация + несоответствие интенту.
2. 🔴 **`Disallow: /_next/image` в robots.txt блокирует ВСЕ картинки сайта** (205 ссылок только на `/catalog`). Google Images не видит ни одного фото товара. Бесплатный источник трафика выключен.
3. 🔴 **Правила для AI-ботов не наследуют запреты.** У групп `GPTBot`, `ClaudeBot`, `PerplexityBot` и т. д. только `Allow: /` — по стандарту robots совпавшая группа отменяет `*` целиком, поэтому AI-краулеры ходят в `/basket`, `/thanks`, `/api/`.
4. 🟠 **Конфликт `noindex` + `Disallow`** на `/delivery`, `/basket`, `/thanks`: краулер не может прочитать `noindex`, потому что ему запрещён заход. URL может попасть в индекс «голым».
5. 🟠 **Тонкий pillar «Застосування».** 5 разделов по 22–38 слов, всего ~200 слов на всю страницу. Под кластер высокочастотных info-запросов нужен объём и подстраницы.
6. 🟠 **Нет страницы «Опт / B2B».** «сухий лід оптом» — жирный коммерческий запрос без посадочной.
7. 🟠 **Товарные страницы без звёзд в выдаче.** Рейтинг есть только у Organization на главной; в `Product` schema нет `aggregateRating` → нет звёзд в товарном сниппете.
8. 🟠 **Главное меню — 5 ссылок.** Категории и гео-страницы живут только в футере, получая минимум внутреннего веса со всех страниц сайта.
9. 🟡 **Гео-охват — 6 городов из ~20 экономически осмысленных.** Доставка НП работает по всей стране, значит нет причин не забирать Винницу, Кривой Рог, Ивано-Франковск, Полтаву и далее.
10. 🟡 **Блог — 7 статей.** Для доминирования в info-выдаче и в AI-ответах нужно 25–30 к концу года плюс регулярное обновление старых.

## 1. Технические находки (детально, с файлами)

### 1.1 🔴 Категория «Харчовий лід» дублирует «Сухий лід»

**Файл:** `src/lib/products.js:189-192`

```js
export async function getProductsByCategory(locale, categoryKey) {
  const all = ...;
  const key = categoryKey === "food-ice" ? "dry-ice" : categoryKey;  // ← здесь
  return all.filter((p) => p.category === key);
}
```

Категория `food-ice` намеренно подменяется на `dry-ice`. Результат: `/catalog/c/harchovyi-lid` и `/catalog/c/suhyi-lid` выводят **один и тот же набор из 15 товаров** — гранулы 3/16/19 мм. Проверено на живом сайте.

**Чем плохо:**
- Google видит две коммерческие страницы с одинаковым товарным блоком и разным вступлением → выбирает одну, вторая теряет позиции (или обе просаживаются).
- Интент не закрыт: человек по запросу «харчовий лід купити», «лід для коктейлів», «кубики льоду» ищет **водяной пищевой лёд** (кубик, краш, сфера), а получает гранулы сухого льда. Отказ.
- В `messages.Categories.foodIce.intro` обещаны «коктейлі, подача страв», а товаров под это нет.

**Решение — выбрать одно:**
- **Вариант А (правильный, если ассортимент планируется):** завести реальные SKU водяного пищевого льда в Sanity (кубик, краш, сфера/шар, фасовки 5/10/20 кг), убрать маппинг, страница становится честной посадочной.
- **Вариант Б (если продавать не планируете):** убрать категорию `food-ice` из `CATEGORIES`, из sitemap и из llms.txt; переписать текст «весь наш сухой лёд — пищевой» в блок на странице `/catalog/c/suhyi-lid` и в FAQ. Один URL вместо двух.

Полумеры («оставить как есть») — худший вариант: страница висит в sitemap и в меню, конкурируя сама с собой.

### 1.2 🔴 robots.txt блокирует все изображения

**Файл:** `src/app/robots.js`, строка `"/_next/image"` в массиве `disallow`.

Все картинки на сайте (товары из Sanity CDN, обложки блога, фото производства) проходят через оптимизатор Next: `/_next/image?url=https%3A%2F%2Fcdn.sanity.io%2F...`. Только на `/catalog` таких ссылок **205 штук**. `Disallow: /_next/image` закрывает их от Googlebot-Image.

**Последствия:** ноль изображений в Google Images и в товарных карточках выдачи; ослаблены Product-сниппеты (`image` в JSON-LD указывает на URL, который краулеру запрещено скачивать).

**Решение:** убрать `/_next/image` из disallow. Если беспокоит краулинговый бюджет — он тут не проблема: сайт на 48 URL.

### 1.3 🔴 AI-боты игнорируют запреты

**Файл:** `src/app/robots.js`

```js
rules: [
  { userAgent: "*", allow: "/", disallow },        // запреты только здесь
  ...aiBots.map((userAgent) => ({ userAgent, allow: "/" })),  // без disallow
]
```

По спецификации robots.txt краулер выполняет **только одну, наиболее специфичную группу**. GPTBot находит свою группу `User-Agent: GPTBot / Allow: /` и группу `*` больше не читает — значит `/basket`, `/thanks`, `/api/`, `/delivery` для него открыты.

**Решение:** передавать тот же массив `disallow` в каждое правило AI-бота:

```js
...aiBots.map((userAgent) => ({ userAgent, allow: "/", disallow })),
```

### 1.4 🟠 `noindex` + `Disallow` — взаимоисключающая пара

`/delivery`, `/basket`, `/thanks` одновременно:
- отдают `robots: { index: false }` в метаданных,
- перечислены в `Disallow` robots.txt.

Краулер, которому запрещён заход, **не увидит** мету `noindex`. Такие URL Google индексирует «вслепую» — по одним только внешним ссылкам, с пустым сниппетом.

**Решение:**
- `/basket`, `/thanks` — убрать из robots.txt `Disallow`, оставить только `noindex` (это канонический способ выкинуть страницу из индекса).
- `/delivery` — страница-легаси, живая (200) и не в sitemap. Правильно: **301 на `/payment-and-delivery`** через `redirects()` в `next.config.mjs`, и тогда убрать её и из robots, и из кода.

### 1.5 🟠 `lastModified` в sitemap — всегда «сегодня»

**Файл:** `src/app/sitemap.js` — `const lastModified = new Date()`.

Каждая регенерация sitemap (раз в час по `revalidate = 3600`) проставляет всем 48 URL текущую дату. Google быстро распознаёт такой шаблон и перестаёт доверять `lastmod` вообще — теряется механизм «подскажи, что реально обновилось».

**Решение:** для товаров и статей брать реальный `_updatedAt` из Sanity (в `lib/blog` уже есть `post.updatedAt` — используется в `articleSchema`). Для статических страниц — зафиксированную дату последней правки контента (константа рядом с путём).

**Главная проблема — LCP.** LCP-элементом Chrome выбирает **декоративное облако** из `HeroClouds` (Cloud 1, `cloud-right.png`, 1012×289), а не фон Hero. Фон весит 9 КБ и имеет `priority`, а облако весило до 96 КБ.

**Что уже сделано:**
- ❌ Попытка дать облакам `priority` — **провалилась**: LCP 5,4 → 9,4 с. Три preload-а по 185 КБ на Slow 4G забивают канал раньше CSS и шрифтов. Откачено, в компоненте оставлен комментарий, чтобы не повторяли.

**LCP всё ещё далёк от цели и упирается не в микрооптимизации, а в решение по Hero.** Варианты, по убыванию эффекта:
1. Отказаться от облаков как от DOM-картинок в первом экране — свести их в один спрайт/CSS-слой либо вынести за пределы первого экрана. Тогда LCP-элементом станет фон (9 КБ) или заголовок.
2. Сократить число облаков в первом экране с 4 до 1–2.
3. Уменьшить `h-[864px]` Hero — сейчас первый экран огромный, в него попадает много тяжёлого.

**Остальные резервы из отчёта:** render-blocking CSS 610 мс (2 файла, 33,6 КБ), unused JS 276 КБ и 8 длинных задач (NextUI + framer-motion) — это TBT 410 мс, legacy JS 11 КБ, unused CSS 28 КБ.

**Не замерены:** `/catalog`, категория, товарная, гео — прогнать отдельно. INP полевой — только после накопления трафика в GSC.

## 2. Контентные и коммерческие пробелы

### 2.1 Категорийные страницы — недобор глубины

Сейчас у категории: H1, вступление 92–187 слов, сетка товаров, ссылки на другие категории. Этого хватает, чтобы страница существовала, но мало, чтобы выигрывать у Prom.ua по «сухий лід купити».

**Чего не хватает на каждой категории:**
- SEO-текст 400–700 слов (сейчас 92–187) с раскрытием подтем: размеры гранул, фасовки, для чего, как хранить, доставка;
- **FAQ-блок 4–6 вопросов, специфичных для категории** + `FAQPage` schema (компонент `FaqSection` уже готов, данные — в `messages.Categories.<key>.faq`);
- `ItemList` / `CollectionPage` JSON-LD со списком товаров и ценами (сейчас у категорий вообще нет разметки, кроме крошек);
- блок «Как выбрать» (таблица гранула → задача);
- ссылки на профильные статьи блога и на гео-страницы;
- блок доверия: производство, наличие, сроки (данные есть в `Usp`).

### 2.5 Внутренняя перелинковка

**Проблема:** главное меню — 5 ссылок (`routes` в `src/utils/routes.js`): Главная, Каталог, Оплата и доставка, Блог, Контакты. - **Дрогобич**, **Стрий**, **Червоноград**.

### Нужны ли области отдельными страницами

**Скорее нет.** Запросы вида «сухий лід Київська область» имеют низкую частотность и почти всегда перекрываются страницей города. Вместо отдельных URL под области:
- добавить в каждую городскую страницу абзац «Доставляємо також у [3–5 населённых пунктов области]» — забирает хвостовые запросы без создания тонких страниц;
- в `areaServed` разметки `Service` рядом с городом указывать область.

Исключение — **Київська область**: имеет смысл как отдельная страница только потому, что там физический склад и собственная доставка (реальное преимущество, о котором есть что писать 600+ слов). Остальные области — нет.

### 🔒 Правило масштабирования (важно)

Гео-страницы для городов без склада строятся по одному шаблону, и при 20+ городах возникает риск, что Google расценит их как doorway-страницы.

**Жёсткие требования к каждой новой странице:**
1. Минимум **60 % уникального текста** — не переставленные слова, а реально разные сценарии: местные отрасли, типы заказчиков, сезонность, конкретные условия доставки.
2. Локальный FAQ — **свои 3 вопроса**, не копия киевских.
3. Разные метатеги и разный H1-угол (не «Сухий лід у X» × 20 раз с одинаковым описанием).
4. Не более **4–6 новых городов за релиз** — с паузой в 3–4 недели, чтобы отследить в GSC, что предыдущая партия индексируется и получает показы, а не оседает в «Обнаружена — не проиндексирована».
5. Если по городу нет ни одного отличающегося сценария — города не добавлять.

**Целевой охват к концу года:** 6 → 16–18 городов + 4–6 спутников. Не 40.

## 9. Как мерить

**Еженедельно:** GSC — показы и клики по группам URL (категории / гео / блог / товары); новые запросы в топ-20.

**Ежемесячно:**
- позиции по ядру: `сухий лід`, `сухий лід купити`, `сухий лід київ/львів/+новые города`, `сухий лід оптом`, `харчовий лід`, `термобокс для льоду`, `очищення сухим льодом`, `сухий лід для весілля`;
- индексация: сколько URL в индексе против sitemap (сейчас 48 → цель ~110–130 к концу квартала);
- AI-видимость: ручной чек 15–20 вопросов в 4 системах;
- GA4: конверсии в заявку по источникам, отдельный сегмент AI-рефереров;
- Clarity: карты кликов на новых посадочных, глубина скролла на категориях и гео.

**Ежеквартально:** CWV по полевым данным, аудит битых ссылок и дублей, ревизия конкурентов (tiz-ice, ice-cube, elmemesser, sektorgaza), обновление старых статей.

**Целевые ориентиры на квартал:** URL в индексе 48 → 110+; статей 7 → 20; городов 6 → 14+; Google-отзывов 9 → 30+; органический трафик — задать базу по GSC на неделе 1 (без неё цифра роста будет выдуманной).

## 10. Что нужно от бизнеса

Эти пункты нельзя закрыть из кода — без них часть задач встанет:

1. **Сертификаты** — сканы (пищевая CO₂, паспорта качества, допуски).
2. **Реквизиты** — ФОП/ТОВ, ЄДРПОУ, юридический адрес.
3. **Кейсы** — 5–7 клиентов, согласных на публикацию (задача, объём, результат; логотип — по возможности).
4. **Google Business Profile** — доступы или подтверждение, что львовская точка заведена.
5. **Подтвердить ассортимент:** продаёте ли водяной пищевой лёд; оказываете ли услугу криобластинга (не только продажа аппарата); есть ли аренда термобоксов; готовы ли к фасовкам 1–2 кг и позициям 100+ кг.
6. **Фото и видео** — производство, криобластинг в работе, эффект тумана, отгрузки. Нужны для кластерных страниц, YouTube и обновления статей.
7. **Ценовая политика** — зафиксировать, честна ли «від 55 грн/кг» на главной при минимальной покупаемой 60 грн/кг.
